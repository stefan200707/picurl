# Анализ ошибок и пути решения

В данном документе описаны причины возникновения ошибок парсинга для запроса:
> "Ищем студию или однушку, бюджет до 8 млн, черновая отделка, хотя нет, лучше с отделкой под ключ, заселение в этом году, метро Ховрино, площадь 30-40 метров, подешевле, этаж 10-15."

## 1. Не поймана отделка (под ключ в итоге)
**Причина:** В функции `extract_finish` (файл `app/parsing/rules.py`) собираются все упоминания отделки (и `True`, и `False`), сортируются по порядку их появления в тексте, после чего возвращается *первое* найденное значение (`candidates[0][1]`). Поскольку "черновая отделка" (False) стоит раньше, чем "с отделкой под ключ" (True), побеждала черновая отделка.
**Путь решения:** Изменить логику так, чтобы приоритет отдавался последнему упоминанию в тексте, так как пользователи часто уточняют или меняют своё мнение по ходу запроса ("хотя нет, лучше..."). Возвращать `candidates[-1][1]`.

## 2. Нет метро в URL
**Причина:** Сущность "Ховрино" успешно находится через rapidfuzz-матчер (по словарю `metro.json`), но в самом файле `app/reference/metro.json` для этой станции отсутствуют поля `slug` и `id`. При сборке ссылки в `url_builder.py` станции без слага (при единичном выборе) или без id (при мульти-выборе) игнорируются и не попадают в URL.
**Путь решения:** Вручную добавить поля `"slug": "khovrino"` и `"id": "7dd714fc-fc31-11e5-8276-005056885dfb"` (или другой корректный GUID из API ПИКа) для записи "Ховрино" в файл `app/reference/metro.json`.

## 3. Не указана этажность ("этаж 10-15")
**Причина:** Регулярные выражения в `extract_floor` (например, `_FLOOR_RANGE_C` = `r"\b(\d+)\s*[-–—]\s*(\d+)\s+этаж\w*"`) ожидают слово "этаж" *после* диапазона чисел ("10-15 этаж"), либо слово "этаж" с предлогом "с" (`_FLOOR_RANGE_B` = `r"\bэтаж\w*\s*[—:\-]?\s*с\s+(\d+)\s+(?:по|до)\s+(\d+)"`). Конструкция "этаж 10-15" не попадала ни под один из существующих паттернов.
**Путь решения:** Добавить новый паттерн `_FLOOR_RANGE_D = re.compile(r"\bэтаж\w*\s*[—:\-]?\s*(\d+)\s*[-–—]\s*(\d+)")` и включить его в цикл поиска в `extract_floor`.

## 4. Заселение в этом году
**Причина:** Функция `extract_ready` искала только слова, явно означающие сданный дом ("заселение сразу", "готовый", "сдан"). Фраза "в этом году" не распознавалась как фильтр по сроку сдачи.
**Путь решения:** Написать отдельное правило `extract_settlement_year` (или дополнить существующее), которое ищет маркер "заселение/сдача в этом году" и устанавливает поля `settlement_year_from` и `settlement_year_to` равными текущему году.

Все эти исправления были внесены в кодовую базу.
