# Текущая стадия проекта и изменения за последние 2 часа

## Текущая стадия проекта

Проект **picurl** находится на завершающей стадии (Milestone 5 достигнут). 
Основной пайплайн детерминированного парсинга текстовых запросов полностью собран, протестирован (включая E2E и стресс-тесты) и работает стабильно. 

Завершена интеграция опционального слоя **ИИ-обогащения (v2)** для обработки сложных семантических и гео-пространственных запросов, которые не покрываются регулярными выражениями. 
Для ИИ-слоя реализованы:
- База Знаний на основе PostgreSQL 15+ с расширением pgvector.
- Пайплайн обогащения через LLM-провайдера.
- Инфраструктура самообучения и промоушена накопленных ИИ-фактов обратно в детерминированные JSON-справочники.
- Интеграционные тесты полного цикла ИИ-обогащения.

На данный момент система переведена в рабочий режим с **включенным по умолчанию** ИИ-обогащением.

## Изменения за последние 2 часа (хронологически)

### 1. Доработка логики отбора кандидатов для ИИ и защита от пустых запросов (13:32 - 13:33)
**Коммиты:** `6a008c7`, `39b1e44` ("task(f3131950): промтт")
**Изменённые файлы:** `app/geo/candidates.py`, `app/ai/enrichment.py`

*   **Увеличение лимита кандидатов:** В `app/geo/candidates.py` константа `SHORTLIST_LIMIT` была увеличена с 20 до 50. Это даёт LLM более широкий выбор вариантов при fallback-сценариях.
*   **Fallback при пустой выдаче:** В логику `build_candidate_shortlist` добавлен механизм отката. Если жёсткий гео-фильтр отсёк абсолютно всех кандидатов (например, из-за ложного срабатывания fuzzy-поиска метро), и при этом пользователь не запрашивал конкретные ID ЖК, функция повторно пытается собрать кандидатов уже без учета гео-фильтра.
*   **Защита обогащения:** В `app/ai/enrichment.py` добавлена проверка на пустой список кандидатов. Если `build_candidate_shortlist` возвращает пустой список, ИИ-обогащение прерывается, возвращается `EnrichmentResult.failed()`, а в список `warnings` добавляется предупреждение: `"Список кандидатов пуст"`.
