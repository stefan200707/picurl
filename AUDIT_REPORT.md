# AUDIT_REPORT.md — ревью-аудит репозитория picurl

Дата аудита: 2026-07-22. Аудит проведён без изменений кода — сверка заявленного
(CLAUDE.md/README/docs) с фактическим состоянием файлов через чтение и grep.

## 0. Несоответствие постановки задачи и реальной структуры репозитория

Задание просит проверить `backend/`, `agent-manager/`, `frontend (src/, hooks,
api-client)`. **Ни одной из этих директорий в репозитории нет.** Фактическая
структура — единственный Python-бэкенд `picurl` (FastAPI, без фронтенда и без
отдельного agent-manager сервиса), что подтверждено `Glob`/`git`-деревом и
соответствует описанию в `CLAUDE.md`. Поэтому аудит применён к реальным
эквивалентам:

- «backend» → `app/` (`api/`, `parsing/`, `pik/`, `reference/`, `ai/`, `geo/`),
  `tests/`, миграции (`app/ai/migrations/`).
- «frontend/agent-manager» — отсутствуют физически; интерфейсом пользователя
  служит автогенерируемый Swagger UI (`/docs`), собственного UI-кода нет.
  Раздел ESLint/TS-конвенций из задания неприменим — в проекте нет ни одного
  `.ts/.tsx/.js`-файла (только Python + Markdown + JSON + SQL).

## Явные допущения (пункты из "Prompt review notes")

1. **Версии ruff/ESLint.** ESLint неприменим (TS/JS в проекте нет). Ruff-версия
   не пиновится к патчу (`pyproject.toml`: `ruff>=0.8`), поэтому находки ниже
   сверены с конфигурацией `[tool.ruff]`/`[tool.ruff.lint]` в `pyproject.toml`
   (`select = E,W,F,I,UP,B,SIM,C4,RUF`, `line-length=100`) — то есть с
   актуальными для проекта правилами, а не с ruff-default набором.
2. **"Неиспользуемые" файлы.** Dev-зависимости (`dependency-groups.dev`) и
   тестовые фикстуры (`tests/conftest.py`, `tests/**/conftest.py`) исключены из
   кандидатов на удаление — это часть тестовой инфраструктуры, не мусор.
   Примеры в `docs/` и `prompts/` тоже не кандидаты сами по себе (они читаются
   людьми/агентами по ссылке из `CLAUDE.md`), кандидатами являются только файлы
   вне этой карты ссылок.
3. **"Не читается ИИ-агентами".** Критерий — фактическая проверка: файл
   упомянут в `CLAUDE.md`, `.claude/skills/**/SKILL.md` или ином
   `project_context_blocks`-источнике (см. системный промпт) **или** на него
   есть ссылка/импорт из кода/документа, который сам читается. Если файл не
   импортируется кодом и не упомянут ни в одном из этих мест — считается не
   читаемым агентами по умолчанию (агент не наткнётся на него без явного
   листинга директории).
4. **"Актуальность логики".** Список known-deprecated модулей в проекте не
   ведётся, поэтому устаревшая логика определялась через: (а) явные
   противоречия между кодом и `CLAUDE.md`/`README.md`/`docs/*.md`
   (документация — источник "как должно быть", код — источник истины "как
   есть"); (b) закомментированный код с пометками "пока что"; (c) поля/функции
   без единого вызова в проде (только тесты или ничего).

## 1. Критические находки: архитектура ИИ-обогащения не соответствует документации

Это самая важная группа находок — она искажает представление о поведении
сервиса как для читателей `README.md`/`CLAUDE.md`, так и для будущих
агентов, которые будут опираться на документацию.

### 1.1 `app/ai/enrichment.py:189-202` — фактический fallback-гейт отключён

```python
async def enrich(...):
    # Пока что все запросы идут в нейронку
    # if not criteria.poi_requirements and not criteria.center_requested:
    #     return EnrichmentResult.noop()
    ...
    # Пока что полностью все запросы идут через нейронку (полное обогащение)
    # if fully_resolved(known, criteria, candidates):
    #     return EnrichmentResult.from_deterministic(known)
```

`CLAUDE.md` (раздел «Архитектура ИИ и Базы Знаний») и `README.md` утверждают:
«ИИ-обогащение работает как ограниченный fallback... основной пайплайн
полностью самодостаточен», «Никаких LLM... в рантайме». Фактически: любой
запрос, для которого `build_candidate_shortlist()` возвращает непустой
шорт-лист ЖК (а он почти всегда непустой — до `SHORTLIST_LIMIT=50` кандидатов
без локационного фильтра), **всегда** уходит в LLM/Antigravity, даже если
`poi_requirements`/`center_requested` пусты и детерминированный парсинг
полностью справился. Это подтверждено и тестом
`tests/integration/test_ai_learning_loop.py:296-309` (Scenario 3): после
успешного «promotion» фактов (наблюдаемость ≥ порога) запрос всё равно уходит
в ИИ (`ai_used=True`), хотя по документации после промоушена система должна
отвечать детерминированно.
- **Рекомендация (fix):** либо раскомментировать гейт и `fully_resolved()`
  (вернув документированное поведение «fallback только когда нужно»), либо
  снять несоответствие в `CLAUDE.md`/`README.md`, явно зафиксировав текущее
  поведение «ИИ вызывается всегда, если есть кандидаты» как временное решение
  с датой/тикетом. Оставлять закомментированный код и противоречащую
  документацию одновременно — вводит в заблуждение.

### 1.2 `app/geo/candidates.py:122-142` (`fully_resolved`) — код без единого вызова из прод-пути

`fully_resolved()` юнит-тестируется (`tests/geo/test_candidates.py:101,115`),
но не вызывается нигде в `app/ai/enrichment.py` (вызов закомментирован, см.
1.1). Функция мертва с точки зрения реального пайплайна.
- **Рекомендация (fix):** либо подключить обратно (см. 1.1), либо (ignore)
  оставить как задел с явной пометкой TODO/issue-ссылкой вместо
  «пока что»-комментария без даты.

### 1.3 `README.md:10` — ложное утверждение "Никаких LLM... в рантайме"

Текст: «Парсинг полностью **детерминированный**... Никаких LLM или медленных
внешних API в рантайме». Это верно только для базового пайплайна, но
`AI_ENRICHMENT_ENABLED: bool = True` по умолчанию (`app/config.py:11`), и, как
показано в 1.1, ИИ фактически вызывается почти всегда. `README.md` даже не
упоминает поля `ai_used`/`ai_cache_hit`/`ai_explanation` в примере ответа
(строки 46-59), хотя они есть в реальной модели ответа
(`app/api/schemas.py:49-59`).
- **Рекомендация (fix):** обновить `README.md` — добавить раздел про
  ИИ-обогащение (как в `CLAUDE.md`) и убрать/уточнить фразу про «никаких LLM».

### 1.4 `app/config.py:11-16` — противоречивые дефолты провайдера/модели

```python
AI_PROVIDER: str = "claude"
...
AI_MODEL_NAME: str = "gemini-3.5-flash"
```
Провайдер по умолчанию — `claude` (используется Anthropic SDK и требует
`ANTHROPIC_API_KEY`), но имя модели по умолчанию — модель Gemini
(`gemini-3.5-flash`), которая передаётся именно в Anthropic-клиент
(`app/ai/client.py:108`, `call_claude`) и там бессмысленна. Это прямое
следствие правки, описанной в стрей-файле `explanation.md` (см. раздел
«Кандидаты на удаление»): там честно зафиксировано, что было исправлено
только имя модели, но не сам провайдер. Итог — с дефолтными настройками (без
`.env`) и заданным `ANTHROPIC_API_KEY` сервис отправит в Anthropic API
несуществующее имя модели `gemini-3.5-flash` и получит ошибку от API.
- **Рекомендация (fix):** привести дефолты в согласованное состояние — либо
  `AI_PROVIDER="antigravity"` + `AI_MODEL_NAME` для Gemini, либо
  `AI_PROVIDER="claude"` + `AI_MODEL_NAME="claude-haiku-4-5"` (реальная
  Claude-модель, упомянутая в `CLAUDE.md`/стрей-файлах).

## 3. Нарушения конфигурации ruff (line-length=100, `select=E,W,F,I,UP,B,SIM,C4,RUF`)

### 3.1 E501 (длина строки > 100) в исходном коде

- `app/parsing/rules/rooms.py:22` — строка регэкспа комнатности (>120 символов).
- `app/parsing/rules/price.py:22` — строка регэкспа диапазона цены (>150 символов).

Оба нарушают `line-length = 100` из `pyproject.toml`. Учитывая, что в проекте
`ruff format --check` — часть команды проверки (`.workflow-ai/verify.sh`), эти
строки либо не проходят текущий CI-скрипт, либо `ruff format` их не считает
нарушением (не исключено, что `ruff format` не рвёт длинные строковые
литералы/f-строки — но `ruff check` (E501) обязан их пометить).
- **Рекомендация (fix):** разбить регэксп-строки через неявную конкатенацию
  соседних строковых литералов (`(\n    r"..."\n    r"..."\n)`), как это уже
  сделано в других файлах пакета `rules/` (например, `app/parsing/rules/time.py`,
  `app/parsing/rules/poi.py`).

### 3.2 E501 в тестах (низкий приоритет)

- `tests/pik/test_url_builder.py:11,22,39`
- `tests/integration/test_build_url_e2e.py:51`

Длинные литералы URL в `assert ... == "https://www.pik.ru/search/..."`.
Формально то же правило E501 (тесты не исключены из `testpaths`/lint-скоупа).
- **Рекомендация (ignore/fix):** низкий приоритет — либо оставить (частый
  случай для URL-ассертов, можно точечно добавить `# noqa: E501`), либо
  вынести ожидаемый URL в отдельную переменную с переносом через `+`.

### 3.3 B014 (`flake8-bugbear`, `select` включает `B`) — избыточный/дублирующий except

`app/ai/enrichment.py:230`:
```python
except (ValueError, Exception) as e:
```
`ValueError` — подкласс `Exception`; перечисление обоих в одном except-кортеже
избыточно и обычно ловится правилом B014 «redundant exception types». Плюс это
просто вводит в заблуждение: `except Exception` и так ловит `ValueError`.
- **Рекомендация (fix):** заменить на `except Exception as e:` (весь смысл
  сохраняется — далее код всё равно проверяет `isinstance(e, (...))`, чтобы
  решить, ретраить/логировать или `raise e` как есть).
