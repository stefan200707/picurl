# Карта и распознавание мест в запросе

Этот отчёт описывает текущий путь от текста пользователя до фильтров pik.ru и
`map_config` в ответе `POST /build-url`. Основные точки реализации:
`app/parsing/parser.py`, `app/parsing/rules/`, `app/geo/candidates.py`,
`app/pik/location_fallback.py`, `app/geo/yandex_maps.py` и `app/api/endpoints.py`.

## Общий поток

1. `parse(text)` извлекает параметры квартиры и места в `Criteria`. Правила
   распознают формулировки близости и времени; `entity_match` сопоставляет
   названия метро, округов, районов и ЖК с локальными JSON-справочниками.
   Неопознанное и неподдерживаемое попадает в `warnings` или
   `option_candidates`.
2. Опциональное `enrich` может дополнить критерии. Ориентиры и другие ответы ИИ
   сверяются со справочниками; расстояния считает код, а не модель. Для
   ориентиров, POI, центра и классов станций гео-слой выбирает ЖК по известным
   координатам, расстояниям или POI-кэшу. Результат влияет на список ЖК в
   ссылке. Дополнительный гео-фолбэк пересекается с выбранными ЖК; если условия
   несовместимы, ответ сообщает об этом в `warnings`.
3. `build_url` формирует ссылку на `pik.ru/search`, а `validate` пытается
   проверить выдачу. Ссылка и карта — разные представления запроса: карта не
   участвует в построении URL или в подсчёте `result_count`.
4. После этого `build_map_context(criteria, text)` независимо выбирает точки и
   строит данные для карты. Ответ содержит `map_config`, который может быть
   `null`. При этом ссылка на pik.ru может быть успешно построена.

## Что означает упоминание места

| Запрос пользователя | Критерий и влияние на ссылку | Точка Б на карте |
| --- | --- | --- |
| «у метро Черкизовская» | Станция находится по имени в `metro.json`; в ссылку идёт локационный фильтр либо гео-фолбэк по ЖК. | Первая распознанная станция с координатами. |
| «рядом с МГУ», «самую ближайшую к МГУ», «у МГУ не дальше 1 км» | Имя/алиас из `landmarks.json` после маркера близости превращается в `landmark_requirements`. ЖК ранжируются или отсекаются по haversine; суперлатив ищет ближайшие, явная дистанция задаёт границу. | Первый распознанный ориентир. |
| «рядом со школой», «парк в 500 м» | `poi_requirements`: категория и, если указана, дистанция проверяются по локальному POI-кэшу, когда категория в нём собрана; подтверждённые ЖК сужают ссылку. Пробелы данных отражаются в `warnings`. | Отдельный адрес школы или парка не определяется: у категории нет единственной точки Б. |
| «в центре» | `center_requested` сужает ЖК по известному признаку центральности. | Фиксированная точка «Центр Москвы (Кремль)». |
| «в районе …», «в округе …», «внутри/за МКАД» | Локационные фильтры или гео-сужение ЖК. | Сами по себе район, округ и МКАД не дают точку Б. |
| «у любого метро», «рядом с МЦД» | `station_class_requirements` выбирает ЖК по расстоянию до подходящих станций. | Класс станций сам по себе не выбирает одну станцию назначения. |
| «ЖК …» без назначения | Названный ЖК участвует в фильтрации ссылки. | Точка Б отсутствует; на карте может быть только маркер ЖК. |

Приоритет выбора точки Б в `yandex_maps.py`: первый
`landmark_requirements` → первая станция из `criteria.metro`, для которой есть
координаты → прямое вхождение имени или алиаса ориентира в исходный текст →
`center_requested` → отсутствие точки. Это **одна** точка назначения, даже если
в запросе несколько мест. Проверка имени/алиаса на последнем текстовом шаге —
простое вхождение без контекстной проверки близости; поэтому точка карты может
не совпадать с тем, что реально сузило ссылку.

## Как строятся точки и маршруты

- Точка А — ЖК с координатами из `complexes.json`. Если в `criteria.complexes`
  есть ЖК с координатами, берутся они; иначе для карты берутся все ЖК справочника
  с координатами. Эндпоинт не передаёт в `build_map_context` итоговый список
  `blocks` из URL или фактические результаты pik.ru. Поэтому подпись
  `all_complex_routes` означает маршруты из **пула карты**, а не доказанный
  перечень ЖК выдачи.
- Без точки Б возвращается конфигурация с первым ЖК в точке А, без маршрута и
  списка маршрутов. Если нет ни одного ЖК с координатами, `map_config=null`.
- При наличии обеих точек маршрут рассчитывается для каждого ЖК пула. Маршруты
  сортируются по `duration_sec`; основной — самый быстрый, а
  `all_complex_routes` содержит первые десять. Если запрошен лимит минут,
  основной берётся из укладывающихся в лимит, когда такие есть; иначе всё равно
  берётся самый быстрый. Лимит **не отсекает** остальные маршруты и сам по себе
  не меняет список ЖК ссылки на этом этапе.
- `detect_travel_mode` выбирает способ: `time_on_transport` даёт автомобиль при
  словах «машин», «авто», «автомобил», иначе общественный транспорт;
  `time_on_foot` даёт пеший режим. Если эти поля пусты, способ ищется в тексте:
  автомобиль → общественный транспорт → велосипед/самокат; по умолчанию пешком.
  Поля времени парсера относятся к доступности **метро** в URL (`timeOnFoot`,
  `timeOnTransport`); карта использует их же как лимит до выбранной точки Б,
  даже когда точка Б — ориентир или центр.
- Если настроен ключ маршрутизации и есть HTTP-клиент, `calculate_route`
  пробует Яндекс Routing API. При ошибке, ответе не `200` или отсутствии ключа
  время оценивается локально: haversine × коэффициент извилистости / средняя
  скорость (для транспорта добавляется время ожидания). Полилиния такого
  маршрута синтетическая, а `yandex_maps_url` открывает маршрут на Яндекс.Картах.
  Оценочные минуты и метры не следует принимать за подтверждённый дорожный
  маршрут.

## Отображение и отдельный запрос маршрута

`GET /map` и `/` отдают вспомогательную страницу
`app/templates/index.html`. Она загружает JS API Яндекс.Карт, вызывает
`POST /build-url`, рисует маркеры А/Б и полилинию из `map_config`, показывает
время и список маршрутов. При выборе другого способа движения страница вызывает
`POST /api/geo/route` с координатами А/Б и режимом; ответ содержит основной
маршрут и расчёты для четырёх режимов. Этот вызов обновляет показанный маршрут,
но не пересчитывает ссылку на pik.ru и список ЖК. Без загруженного JS API
страница не рисует карту; JSON-ответ `/build-url` остаётся доступен через API.

Смежные детали выбора ЖК: [гео-сужение](geo-narrowing.md),
[POI-кэш](poi-cache.md), [URL-фильтры](pik-url-schema.md).
