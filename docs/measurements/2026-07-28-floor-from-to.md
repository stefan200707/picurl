# Замер: семантика `floorFrom` / `floorTo` на pik.ru

**Дата:** 2026-07-28
**Повод:** сообщение о дефекте — «ссылка с `floorFrom=7` показывает на pik.ru РОВНО
седьмой этаж, а не „седьмой и выше“».
**Итог:** дефект **не подтвердился**. `floorFrom=N` означает «этаж N и выше»,
`floorTo=N` — «этаж от минимального до N». Схема, код и генерируемые ссылки верны.
Источник ложной тревоги найден и описан в разделе 5 — это **подпись чипа** в UI сайта,
а не выдача.

Все числа ниже — живые, получены в один день на одном стенде.
Полигон: ЖК «Руставели 14» (`blocks=477`), однокомнатные (`rooms=1`).
Этажность корпусов: **2…21** (минимальный доступный этаж — 2, максимальный — 21).

---

## 1. Бэкенд `api.pik.ru/v2/filter` (curl)

| # | Query | `count` |
|---|---|---|
| 1 | `blocks=477&rooms=1` (baseline) | **55** |
| 2 | `blocks=477&rooms=1&floorFrom=7` | **33** |
| 3 | `blocks=477&rooms=1&floorFrom=7&floorTo=7` | **2** |
| 4 | `blocks=477&rooms=1&floorFrom=7&floorTo=50` | **33** |
| 5 | `blocks=477&rooms=1&floorFrom=1&floorTo=50` | **55** |
| 6 | `blocks=477&rooms=1&floorTo=12` | **34** |
| 7 | `blocks=477&rooms=1&floorFrom=1&floorTo=12` | **34** |
| 8 | `blocks=477&rooms=1&floorFrom=12&floorTo=12` | **4** |
| 9 | `blocks=477&rooms=1&floorFrom=1` | **55** |
| 10 | `blocks=477&rooms=1&floorTo=1` | **0** |
| 11 | `blocks=477&rooms=1&floorFrom=99` (контроль «фильтр вообще работает») | **0** |

Что из этого следует:

- **(2) = (4)**: `floorFrom=7` в одиночку тождественно `floorFrom=7&floorTo=<макс>`.
  Одиночная нижняя граница — открытый интервал вверх.
- **(2) ≠ (3)**: 33 против 2. Если бы `floorFrom=7` означало «ровно 7», числа совпали бы.
  Это прямое опровержение исходной гипотезы, ещё до захода на сайт.
- **(6) = (7)**: `floorTo=12` в одиночку тождественно `floorFrom=1&floorTo=12`.
  Одиночная верхняя граница — открытый интервал вниз. Зеркальной болезни у `_FLOOR_MAX`
  нет.
- **(6) ≠ (8)**: 34 против 4 — то же опровержение для верхней границы.
- **(5) = (1)**: диапазон, накрывающий всю этажность, возвращает baseline — диапазонная
  форма исправна и ничего не теряет.
- **(10) = 0** не противоречит трактовке «1…12»: в этом ЖК просто нет квартир на 1 этаже
  (минимальный доступный — 2). Подтверждается пунктом 3 ниже.

> Примечание: baseline здесь 55, а в замере 2026-07-27 (`CLAUDE.md`) было 54 — живой
> остаток продаж меняется день ото дня. На выводы не влияет: все сравнения сделаны
> внутри одного дня.

## 2. Фронт `www.pik.ru` — реальные этажи в выдаче (Chrome, живые клики)

`curl` до фронта не достаёт (Qrator отдаёт **HTTP 401**), поэтому замер сделан реальным
браузером. Извлекались подписи карточек вида «Корпус X, Этаж N из 21».

| URL | Что показал сайт |
|---|---|
| `…&floorFrom=7` | «33 квартиры»; этажи в выдаче: **7, 10, 11, 13, 16, 20, 21** |
| `…&floorFrom=7&floorTo=7` | **2 квартиры**: «Корпус 3.5, Этаж 7 из 21», «Корпус 3.7, Этаж 7 из 21» |
| `…&floorTo=12` | этажи в выдаче: **2, 4, 5, 6, 7, 9, 10, 11** |
| `…&floorFrom=7&floorTo=12` | этажи в выдаче: **7, 9, 10, 11, 12** |

Это решающее наблюдение: при `floorFrom=7` в выдаче физически присутствуют этажи
**10, 11, 13, 16, 20, 21**. Никакого «ровно седьмого» нет. Счётчики сайта (33 и 2)
совпали с бэкендом (строки 2 и 3 таблицы 1) — фронт и API согласованы.

## 3. Фронт — состояние контрола «Этаж»

Секция «Этаж» в панели «Фильтр» — это **два поля с двумя ползунками**, границы
подставляются из фактической этажности выборки:

| Состояние URL | Левое поле | Правое поле | Кнопка |
|---|---|---|---|
| без параметров этажа | `2` | `21` | «55 предложений» |
| `floorFrom=7` | `7` | `21` | «33 квартиры» |

Пустое состояние показывает `2`, а не `1` — отсюда и `floorTo=1 → 0` в таблице 1.

## 4. Какой URL генерирует сам UI сайта (эталон)

Сценарий: чистая выдача `/search/one-room?blocks=477` → «Фильтр» → в левое поле «Этаж»
введено `7` → Tab.

- правое поле **опустело** (не подставилось `21`);
- кнопка применения сразу показала «**33 предложения**» — то же число, что у нашей ссылки;
- после применения адресная строка стала:

```
https://www.pik.ru/search/one-room?blocks=477&floorFrom=7
```

**UI ставит одиночную нижнюю границу без `floorTo`.** Ровно то же генерирует picurl:

```text
parse('однокомнатную квартиру в Руставели 14 от 7 этажа')
  → criteria: {'floor_min': 7, 'rooms': '1', 'complexes': ['Руставели 14']}
  → url:      https://www.pik.ru/search/one-room?blocks=477&floorFrom=7
```

Совпадение побайтовое. Дополнять нижнюю границу верхней **не нужно и вредно**: это
разошлось бы с эталоном.

## 5. Откуда взялось впечатление «ровно седьмой этаж»

Подпись чипа в «Применённых фильтрах» **не различает открытый интервал и точное
значение**:

| URL | Чип | Реальная выдача |
|---|---|---|
| `floorFrom=7` | «**7 этаж**» | 33 кв., этажи 7…21 |
| `floorFrom=7&floorTo=7` | «**7 этаж**» | 2 кв., только этаж 7 |
| `floorTo=12` | «**12 этаж**» | 34 кв., этажи 2…12 |
| `floorFrom=7&floorTo=12` | «7 этаж - 12 этаж» | 5 кв., этажи 7…12 |

Две принципиально разные ссылки (33 квартиры и 2 квартиры) подписаны сайтом
**одинаково** — «7 этаж». Обе одиночные границы читаются как точное значение, хотя
фильтруют интервалом. Это дефект формулировки в UI pik.ru, повлиять на него мы не можем;
единственный надёжный способ прочитать применённый фильтр — открыть панель «Фильтр» и
посмотреть на пару полей (раздел 3) либо на этажи в самих карточках.

## 6. Вывод для проекта

- `docs/pik-url-schema.md` — запись уточнена (семантика описана явно), не исправлена по
  существу: она была верна.
- `app/parsing/rules/floor.py`, `Criteria.to_query_dict()` (`app/parsing/schema.py:429`),
  `app/pik/url_builder.py` — **изменений не требуют**.
- `floorFrom`/`floorTo` подтверждены как реально учитываемые бэкендом
  (строки 2, 3, 6, 8, 11 таблицы 1), поэтому их отсутствие в
  `UNVERIFIED_LOCATION_PARAMS` / `UNVERIFIED_NON_LOCATION_PARAMS`
  (`app/pik/validator.py`) корректно: `result_count` их честно учитывает.

## Как воспроизвести

```bash
# бэкенд
curl -s "https://api.pik.ru/v2/filter?blocks=477&rooms=1&floorFrom=7" | python3 -c 'import sys,json;print(json.load(sys.stdin)["count"])'
curl -s "https://api.pik.ru/v2/filter?blocks=477&rooms=1&floorFrom=7&floorTo=7" | python3 -c 'import sys,json;print(json.load(sys.stdin)["count"])'
```

Фронт — только реальным браузером (`curl` → 401): открыть
`https://www.pik.ru/search?blocks=477&rooms=1&floorFrom=7`, пролистать выдачу до конца и
прочитать подписи «Этаж N из 21» на карточках.
