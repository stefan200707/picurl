# API поиска по карте

Документ описывает текущую реализацию [эндпоинтов](../app/api/endpoints.py),
[HTTP-моделей](../app/api/schemas.py) и [гео-моделей](../app/geo/yandex_maps.py).
Базовый адрес при локальном запуске: `http://127.0.0.1:8000`.
Интерактивный контракт доступен в `/docs`, JSON-схема — в `/openapi.json`.
Перечисленные ручки не требуют токена авторизации.

| Метод и путь | Назначение | Успешный ответ |
|---|---|---|
| `POST /build-url` | Поиск по тексту: ссылка ПИК и данные для карты | `200 application/json` |
| `POST /api/geo/route` | Расчёт маршрутов между заданными координатами | `200 application/json` |
| `GET /map` | Страница поиска с Яндекс.Картами | `200 text/html` |
| `GET /` | Та же страница, без перенаправления; скрыта в OpenAPI | `200 text/html` |

Отдельного API поиска по границам видимой карты, радиусу или полигону нет.
Страница отправляет текст в `/build-url`, а при пересчёте маршрута вызывает
`/api/geo/route`.

## POST /build-url — поиск и подготовка карты

Тело запроса — JSON с обязательным полем `text` (строка длиной не менее одного
символа). Пробелы по краям удаляются перед обработкой.

```sh
curl -X POST http://127.0.0.1:8000/build-url \
  -H 'Content-Type: application/json' \
  -d '{"text":"двушка до 15 млн до 20 минут пешком от МГУ"}'
```

Сервис распознаёт критерии, при возможности обогащает их, собирает ссылку ПИК,
проверяет выдачу и формирует `map_config`.

| Поле ответа | Тип | Значение |
|---|---|---|
| `url` | string | Ссылка на `pik.ru/search` с применёнными фильтрами |
| `criteria` | object | Распознанные критерии в человекочитаемом виде |
| `result_count` | integer или null | Число объектов по данным валидатора ПИК; null при невозможности проверки |
| `warnings` | string[] | Предупреждения о распознавании и ограничениях |
| `warnings_detailed` | object[] | Те же сообщения: `text`, `category`, `severity` |
| `ai_used` | boolean | Обогащение повлияло на результат |
| `ai_failed` | boolean | Попытка обращения к ИИ завершилась ошибкой |
| `ai_cache_hit` | boolean | Использован семантический кэш обогащения |
| `ai_explanation` | string или null | Объяснение обогащения |
| `map_config` | object или null | Конфигурация карты по схеме ниже |

Категории предупреждений: `lost`, `unknown`, `noise`, `capped`, `unverified`,
`degraded`, `info`; уровни: `error`, `warning`, `info`. Тексты и порядок элементов
в `warnings` совпадают с `warnings_detailed`.

### Объект map_config

| Поле | Тип | Назначение |
|---|---|---|
| `api_key` | string или null | Настроенный ключ JS API Яндекс.Карт |
| `script_url` | string | Адрес загрузки JS API 2.1 с языком `ru_RU` |
| `auto_load` | boolean | Признак автоматической загрузки; текущий сборщик возвращает true |
| `center` | number[] | Центр карты `[lat, lon]` |
| `zoom` | integer | Выбранный масштаб |
| `point_a` | GeoPoint или null | Стартовый ЖК |
| `point_b` | GeoPoint или null | Целевая точка |
| `route` | RouteLeg или null | Основной маршрут |
| `all_complex_routes` | RouteLeg[] | До 10 маршрутов от ЖК, отсортированных по `duration_sec` |
| `selected_travel_time_min` | integer или null | Распознанный лимит времени; при маршруте без лимита — его длительность |
| `travel_mode` | string | Способ передвижения (значения ниже) |

Точка Б выбирается по приоритету: первый распознанный ориентир → первая
распознанная станция метро с координатами → название/алиас ориентира в тексте →
центр Москвы, если он запрошен. Произвольный адрес эта ручка не геокодирует.

Для точки А используются выбранные ЖК с координатами. Если таких записей нет,
сборщик берёт все ЖК с координатами из локального каталога. При отсутствии
точки Б возвращается карта первого ЖК, `point_b` и `route` равны null,
`all_complex_routes` пуст. Если нет пригодных ЖК, `map_config` равен null.

Основным выбирается самый быстрый маршрут. Если задан лимит времени и никто
в него не укладывается, всё равно возвращается самый быстрый маршрут.
`all_complex_routes` не отфильтровывается по лимиту времени. Построение карты
не меняет уже сформированную ссылку или критерии: маршруты не являются
подтверждением наличия подходящих квартир в этих ЖК. `result_count` — также
не число маркеров: валидатор ПИК не проверяет часть фильтров, включая локационные.
Подробнее — [гео-сужение](geo-narrowing.md) и [URL-схема ПИК](pik-url-schema.md).

### Ошибки

- `400`: строка состоит только из пробелов; ответ
  `{"detail":"Текст запроса не может быть пустым."}`.
- `422`: отсутствует `text`, передана пустая строка, неверный тип или невалидный JSON;
  стандартный ответ FastAPI с массивом ошибок в `detail`.
- Ошибка проверки выдачи обычно не прерывает поиск: ответ `200`,
  `result_count: null` и предупреждение. Нулевой результат сопровождается
  предупреждением «под критерии ничего не найдено».

## POST /api/geo/route — маршрут между точками

Принимает JSON с обязательными `origin` и `destination` типа `GeoPoint`.
Поле `travel_mode` необязательно, по умолчанию `pedestrian`.

| travel_mode | Способ передвижения |
|---|---|
| `pedestrian` | Пешком |
| `driving` | На машине |
| `transit` | Общественный транспорт |
| `bicycle` | Велосипед |

```sh
curl -X POST http://127.0.0.1:8000/api/geo/route \
  -H 'Content-Type: application/json' \
  -d '{"origin":{"lat":55.7029,"lon":37.5308,"name":"Точка А","point_type":"origin"},"destination":{"lat":55.7028,"lon":37.5305,"name":"Точка Б","point_type":"destination"},"travel_mode":"pedestrian"}'
```

Ответ содержит `route` (`RouteLeg` для запрошенного режима) и `all_modes`
(четыре `RouteLeg` в порядке `pedestrian`, `driving`, `transit`, `bicycle`).
Выбранный режим присутствует и в `route`, и в `all_modes`.
Эта ручка не выполняет поиск квартир и не изменяет ссылку ПИК.

### GeoPoint

| Поле | Тип | Обязательность / значение по умолчанию |
|---|---|---|
| `lat` | number | Обязательно, широта |
| `lon` | number | Обязательно, долгота |
| `name` | string или null | Необязательно, null |
| `address` | string или null | Необязательно, null |
| `point_type` | string | Необязательно, `origin`; для назначения передавайте `destination` |

Координаты в массивах карты и маршрута имеют порядок **[широта, долгота]**.
`point_type` — обычная строка, не enum; даже у `destination` значение по умолчанию
`origin`, если его не задать. Диапазоны широты/долготы моделью не ограничены.

### RouteLeg

| Поле | Тип | Значение |
|---|---|---|
| `origin`, `destination` | GeoPoint | Начальная и конечная точки |
| `travel_mode` | string | Режим передвижения |
| `distance_m` | number | Длина пути в метрах |
| `duration_min`, `duration_sec` | integer | Время в минутах и секундах |
| `formatted_duration` | string | Например, `12 мин пешком` |
| `formatted_distance` | string | Например, `850 м` или `1.2 км` |
| `waypoints` | number[][] | Полилиния `[[lat, lon], ...]` |
| `yandex_maps_url` | string | Ссылка на маршрут в Яндекс.Картах |
| `summary_text` | string или null | Текстовое описание маршрута |

`422` возвращается при отсутствии обязательных точек/координат, неверных типах,
невалидном JSON или неизвестном `travel_mode`. Дополнительные поля моделей
запросов игнорируются, а не вызывают ошибку.

## Расчёт маршрута и настройки

Обе POST-ручки используют один расчёт маршрутов. При наличии HTTP-клиента и
ключа сервис обращается к Яндекс Routing API с тайм-аутом 3 секунды на запрос.
Без ключа, при ошибке обращения или неуспешном HTTP-статусе применяется локальная
оценка: haversine, коэффициент удлинения пути и средняя скорость; для транспорта
добавляется время ожидания. Полилиния в этом режиме синтетическая, а время
не учитывает реальные пробки, расписание или доступность дорог.

В текущей реализации внешний запрос использует `walking` для `pedestrian`,
а для всех остальных режимов — `driving`. Поэтому внешний расчёт `transit` и
`bicycle` не является специализированным расчётом этих видов транспорта.
Ответ не содержит отдельного признака источника расчёта. При отсутствии геометрии
во внешнем ответе полилиния также генерируется локально.

Настройки задаются в окружении или `.env` через [Settings](../app/config.py):

| Переменная | Назначение |
|---|---|
| `YANDEX_MAPS_API_KEY` | Ключ JS API, также резервный ключ для маршрутизации |
| `YANDEX_MAPS_ROUTING_API_KEY` | Приоритетный ключ серверной маршрутизации |
| `YANDEX_MAPS_AUTO_LOAD` | Объявлен в настройках, но текущий сборщик карты его не использует: `auto_load=True` |

Ключ JS API попадает в `api_key` ответа и в URL скрипта HTML-страницы.
В `map_config.script_url` ключ добавляется в ветке с маршрутом; в ветке без
точки Б остаётся URL по умолчанию без ключа.

## GET /map и GET / — готовый интерфейс

Параметры и тело не требуются. Обе ручки возвращают HTML из
`app/templates/index.html`, подставляя URL JS API Яндекс.Карт с настроенным ключом.
Если шаблон отсутствует, возвращается `404` с JSON
`{"detail":"Шаблон карты не найден."}`.

```sh
curl http://127.0.0.1:8000/map
```
