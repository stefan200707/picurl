# Использование ИИ в picurl

## Назначение

Основной путь picurl детерминирован: запрос разбирают регулярные выражения и
RapidFuzz, а URL собирается по локальным справочникам. ИИ — необязательный
fallback для формулировок, которые этот путь не смог надёжно разобрать, и для
выбора из заранее подготовленного списка ЖК. При выключенном или недоступном ИИ
сервис продолжает строить ссылку по распознанным критериям.

Точка подключения ИИ к пользовательскому запросу — `POST /build-url`:
`app/api/endpoints.py` после `parse()` вызывает `app.ai.enrichment.enrich()`, а
уже затем передаёт итоговые критерии в сборщик URL и валидатор.

## Где применяется ИИ

### 1. Извлечение недостающих фильтров из свободного текста

`app.ai.enrichment.resolve_free_text_criteria()` получает полный запрос, уже
распознанные критерии и неразобранные фрагменты. Модель может заполнить только
пустые поля строгой схемы `FreeTextCriteriaAnswer`, например:

- число комнат, цену и площадь;
- этаж и ограничения на первый/последний этаж;
- отделку, готовность, срок заселения и сортировку;
- время до метро и требование показывать только доступные квартиры;
- известный ориентир или категорию объекта окружения (школа, детский сад,
  магазин, парковка, парк/лес, медицина).

Результат модели не переопределяет данные детерминированного парсера. Ориентиры
принимаются только как `slug` из `landmarks.json`, отделка и категории POI —
только как значения известных enum. Неразобранная фраза удаляется из warnings
лишь после успешной валидации результата.

### 2. Сопоставление разговорных формулировок с опциями pik.ru

`app.ai.enrichment.resolve_options()` сопоставляет `option_candidates` с
реальными опциями и группами опций из локальных справочников. Например,
разговорная фраза может быть связана с существующей опцией «Два и более
санузла».

Модель возвращает только `slug` из переданного каталога. Значения вне каталога
отбрасывает `sanitize_option_resolution()`, поэтому ИИ не может добавить в URL
несуществующий фильтр.

### 3. Отбор ЖК по сложным требованиям к окружению

Для требований вроде «в центре, рядом со школой и парком» модуль
`app.geo.candidates` сначала формирует ограниченный список реальных ЖК и
объективных фактов о них. `app.ai.enrichment.enrich()` передаёт этот список
модели, которая выбирает подходящие идентификаторы и формирует объяснение.

Ответ проверяет `sanitize_against_shortlist()`: идентификатор ЖК, которого не
было среди кандидатов, не попадёт в критерии. Если локальные данные уже дают
однозначный ответ, модель не вызывается и используется детерминированный
результат.

### 4. Семантический кэш и база накопленных фактов

`app.ai.embeddings` строит локальные эмбеддинги моделью Sentence Transformers.
Они применяются не для разбора фильтров, а для поиска похожих ранее обработанных
запросов в `ai_semantic_cache` (PostgreSQL + pgvector). При совпадении сохранённый
валидированный ответ используется без повторного вызова LLM.

Подтверждённые результаты сохраняются в `ai_structured_facts`. Команда
`uv run python -m app.ai.promotion` переносит только достаточно часто и уверенно
подтверждённые факты и однозначные алиасы в детерминированные справочники.
Пороги задаются в `app.config.Settings`; единичный ответ модели не промоутится.

### 5. Наблюдаемость ИИ-слоя

Каждый проход `enrich()` best-effort записывается в `ai_call_log`: был ли вызван
провайдер, найден ли ответ в кэше, изменились ли критерии и завершилась ли
попытка ошибкой. Сводка строится командой:

```bash
uv run python -m app.ai.usage_report --days 30
```

Поля ответа API `ai_used`, `ai_failed`, `ai_cache_hit` и `ai_explanation`
показывают клиенту соответственно реальное влияние ИИ, сбой попытки, попадание
в кэш и объяснение результата. `ai_used=false` само по себе не означает ошибку:
модель могла не требоваться или не изменить критерии.

## Что ИИ не делает

- не формирует URL напрямую — это делает `app.pik.url_builder`;
- не создаёт новые фильтры, `slug`, GUID или идентификаторы ЖК;
- не вычисляет расстояния и маршруты: расстояния считает haversine-код, маршруты
  строит интеграция с Яндекс Картами;
- не загружает справочники и POI во время пользовательского запроса;
- не заменяет проверку результата через `app.pik.validator`;
- не является обязательным для запуска и работы базового пайплайна.

Эти границы нужны, чтобы ошибка или галлюцинация модели не расширила выдачу
молча и не породила несуществующий параметр pik.ru.

## Провайдеры и отказоустойчивость

`app.ai.client` поддерживает Claude и Antigravity (`agy`). Провайдер, модель,
ретраи и circuit breaker настраиваются полями `AI_*` в `app/config.py`. Вызов
`agy` выполняется только в режиме `--print`; флаги отключения его ограничений
безопасности запрещены.

Сетевой или модельный сбой не останавливает обработку запроса: пользователь
получает результат детерминированного слоя и warning. Ошибки семантического кэша,
хранилища фактов и журнала вызовов также обрабатываются best-effort.

Инструкции по включению провайдера и БД приведены в `ENABLE_ANTIGRAVITY.md`,
детальная схема гейтов, кэша и жизненного цикла результата — в
`docs/ai-enrichment-architecture.md`.

## Карта реализации

| Место | Роль |
|---|---|
| `app/api/endpoints.py` | включает обогащение в поток `POST /build-url` |
| `app/ai/enrichment.py` | гейты, вызовы ИИ, санитайзеры, merge и fallback |
| `app/ai/client.py` | Claude/Antigravity, ретраи и circuit breaker |
| `app/ai/prompts.py` | системные промпты и передаваемый модели контекст |
| `app/ai/schema.py` | строгие схемы ответов модели |
| `app/ai/embeddings.py` | локальные эмбеддинги запросов |
| `app/ai/memory.py` | факты, семантический кэш и журнал вызовов |
| `app/ai/promotion.py` | перенос подтверждённых знаний в справочники |
| `app/ai/usage_report.py` | отчёт об использовании и пользе ИИ |
| `app/ai/migrations/` | таблицы pgvector, фактов и наблюдаемости |
