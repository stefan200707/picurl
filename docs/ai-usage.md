# Использование ИИ в picurl

picurl превращает текстовый запрос о квартире в ссылку на поиск `pik.ru`. Сначала
работает детерминированный парсер (правила и локальные справочники). Опциональный
ИИ-слой помогает разобрать свободные формулировки, неоднозначные опции и сложные
условия, которые парсер не смог разрешить. Обычные запросы могут обрабатываться
без вызова модели, даже когда ИИ включён.

Модель не формирует URL напрямую и не рассчитывает расстояния. Её ответы
проверяются по доступным справочникам и кандидатам; неподтверждённые значения
отбрасываются, а пользователь получает предупреждение. Без ИИ основной поиск
продолжает работать.

## Быстрый запуск

1. Установите зависимости: `uv sync`.
2. Создайте `.env` из `.env.example` и выберите провайдера:

   ```env
   AI_ENRICHMENT_ENABLED=true
   AI_PROVIDER=antigravity
   AI_MODEL_NAME=gemini-3.5-flash
   ```

3. Для `antigravity` установите CLI `agy` и выполните на машине сервера
   `agy --auth-code`. При необходимости задайте `ANTIGRAVITY_CLI_PATH`.
   Для `claude` установите Claude Code CLI, выполните вход через `claude` и
   укажите `AI_PROVIDER=claude` и подходящее `AI_MODEL_NAME`. На сервере без
   локального входа задайте `ANTHROPIC_API_KEY` либо `CLAUDE_OAUTH_TOKEN`
   (токен из `claude setup-token`). При необходимости задайте `CLAUDE_CLI_PATH`.
   Подробности обоих способов аутентификации — в
   [ENABLE_ANTIGRAVITY.md](../ENABLE_ANTIGRAVITY.md).
4. Запустите сервис: `uv run fastapi dev`. Swagger UI доступен по адресу
   <http://127.0.0.1:8000/docs>.

Для семантического кэша, накопления фактов и журнала вызовов нужна PostgreSQL
15+ с pgvector. Локально её можно подготовить так:

```bash
docker compose up -d postgres
docker exec -i picurl-postgres psql -U postgres -d picurl_ai < app/ai/migrations/01_memory_tables.sql
docker exec -i picurl-postgres psql -U postgres -d picurl_ai < app/ai/migrations/02_ai_call_log.sql
docker exec -i picurl-postgres psql -U postgres -d picurl_ai < app/ai/migrations/03_ai_call_failed.sql
```

По умолчанию `DATABASE_URL` указывает на эту локальную БД; для другой БД задайте
его в `.env`. Если БД недоступна, сервис продолжит работу, но память, кэш и
журнал ИИ не будут доступны. Настройка БД описана в [db-setup.md](db-setup.md).

## Как отправить запрос

В Swagger UI откройте `POST /build-url`, нажмите **Try it out** и передайте:

```json
{"text": "хочу двушку до 20 млн рядом с парком"}
```

Тот же запрос через HTTP:

```bash
curl -X POST http://127.0.0.1:8000/build-url \
  -H 'Content-Type: application/json' \
  -d '{"text":"хочу двушку до 20 млн рядом с парком"}'
```

В ответе `url` содержит ссылку на поиск, `criteria` — применённые критерии,
`warnings` и `warnings_detailed` — нераспознанные или ослабленные условия.
`result_count` может быть `null`, если проверка выдачи не удалась; некоторые
фильтры проверочный эндпоинт pik.ru не учитывает, поэтому смотрите также
`warnings_detailed`. Значение `ai_used=true` означает, что ИИ изменил критерии;
`ai_failed=true` — что попытка вызова модели сорвалась. Если оба поля `false`,
модель не вызывали либо она ответила, но не дала применимых значений.
`ai_cache_hit` показывает использование семантического кэша, `ai_explanation`
содержит пояснение, если оно есть.

## Управление и диагностика

- `AI_ENRICHMENT_ENABLED=false` отключает ИИ и оставляет детерминированный путь.
- Для проверки правок промпта на живой модели установите
  `AI_ENRICHMENT_BYPASS_CACHE=true`. Если запрос уже полностью разрешается
  детерминированно, дополнительно нужен `AI_ENRICHMENT_FORCE=true`. Эти флаги
  предназначены для отладки.
- `uv run python -m app.ai.usage_report --days 7` показывает статистику вызовов
  при доступном журнале в БД.
- `uv run python -m app.ai.promotion --report` показывает кандидатов на перенос
  подтверждённых фактов в справочники. Команда без `--report` выполняет
  промоушен; её используйте после проверки отчёта.

Подробная логика гейтов, валидации ответов и наблюдаемости описана в
[архитектуре ИИ-обогащения](ai-enrichment-architecture.md). Все переменные
окружения и примеры конфигурации находятся в [`.env.example`](../.env.example).
