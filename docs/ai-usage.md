# Использование ИИ в picurl

ИИ в picurl — опциональный слой обогащения запроса. Основной путь остаётся
детерминированным: русский текст разбирают regex-правила и `rapidfuzz`, после чего
`Criteria` преобразуется в ссылку `pik.ru/search`. Модель подключается только для
контекстных, географических и неоднозначных фрагментов, которые нельзя надёжно
обработать локальными правилами.

## Что делает ИИ

ИИ может уточнять запросы наподобие «рядом с парком», «в центре», разрешать
неоднозначные названия опций и дополнять только ещё не заполненные поля `Criteria`.
Модель не строит итоговую ссылку, не рассчитывает расстояния и не может добавлять
произвольные фильтры. Её структурированный ответ проверяется по локальным
справочникам и сформированному приложением списку кандидатов. Невалидные значения
отбрасываются, а исходный фрагмент остаётся в `warnings`.

Если ИИ выключен, не настроены учётные данные или недоступна база памяти, базовый
пайплайн продолжает работать. Ошибка провайдера также не прерывает формирование
ссылки: клиент получает детерминированный результат и признак `ai_failed`.

## Быстрый запуск

1. Установите зависимости и создайте локальную конфигурацию:

   ```bash
   uv sync
   cp .env.example .env
   ```

2. Выберите провайдера в `.env`.

   Antigravity (Gemini через `agy`):

   ```env
   AI_ENRICHMENT_ENABLED=true
   AI_PROVIDER=antigravity
   AI_MODEL_NAME=gemini-3.5-flash
   # ANTIGRAVITY_CLI_PATH=/полный/путь/к/agy
   ```

   CLI `agy` должен быть установлен и авторизован командой `agy --auth-code`.
   Приложение запускает его только в режиме `--print`; отключать защиту разрешений
   для пользовательского текста запрещено.

   Claude через Claude Agent SDK и локальный Claude Code CLI:

   ```env
   AI_ENRICHMENT_ENABLED=true
   AI_PROVIDER=claude
   AI_MODEL_NAME=claude-sonnet-5
   ANTHROPIC_API_KEY=sk-ant-...
   # CLAUDE_CLI_PATH=/полный/путь/к/claude
   ```

   Вместо API-ключа можно задать `CLAUDE_OAUTH_TOKEN`, полученный командой
   `claude setup-token`. На macOS допускается не задавать оба значения: SDK использует
   авторизацию Claude Code из keychain. Для production предпочтителен API-ключ с
   отдельной квотой.

3. Поднимите PostgreSQL с pgvector и примените все миграции:

   ```bash
   docker compose up -d postgres
   psql "$DATABASE_URL" -f app/ai/migrations/01_memory_tables.sql
   psql "$DATABASE_URL" -f app/ai/migrations/02_ai_call_log.sql
   psql "$DATABASE_URL" -f app/ai/migrations/03_ai_call_failed.sql
   ```

   Значение для локального compose:

   ```env
   DATABASE_URL=postgresql://postgres:password@localhost:5432/picurl_ai
   ```

   База хранит семантический кэш, подтверждённые факты и журнал вызовов. Она повышает
   скорость и даёт накопление знаний, но не заменяет валидацию ответа модели.

4. Запустите API:

   ```bash
   uv run fastapi dev
   ```

5. Откройте `http://127.0.0.1:8000/docs` и выполните `POST /build-url`, например:

   ```json
   {
     "text": "хочу двухкомнатную квартиру рядом с парком до 20 млн"
   }
   ```

## Как читать результат

Ответ `POST /build-url` содержит следующие признаки:

| Поле | Значение |
|---|---|
| `ai_used` | ИИ действительно изменил итоговые критерии. |
| `ai_failed` | Попытка вызова была, но модель не ответила или сработал circuit breaker. |
| `ai_cache_hit` | Результат получен из семантического кэша. |
| `ai_explanation` | Краткое объяснение обогащения, если оно было. |
| `warnings` | Нераспознанные, неподдержанные или отброшенные части запроса. |

`ai_used=false` не означает ошибку: модель могла не понадобиться, быть выключена,
ответить без полезных дополнений или вернуть значения, не прошедшие проверку.
Комбинация `ai_used=false`, `ai_failed=true` означает безопасную деградацию на
детерминированный результат.

## Отключение и отладка

Чтобы полностью исключить обращения к модели:

```env
AI_ENRICHMENT_ENABLED=false
```

Для проверки изменений ИИ-логики доступны два независимых флага:

```env
AI_ENRICHMENT_BYPASS_CACHE=true
AI_ENRICHMENT_FORCE=true
```

- `AI_ENRICHMENT_BYPASS_CACHE` запрещает чтение старого семантического ответа, но
  сохраняет запись новых ответов.
- `AI_ENRICHMENT_FORCE` пропускает детерминированный гейт и принудительно вызывает
  модель. Используйте оба флага только при локальной отладке, затем удалите их из
  окружения.

Секреты (`ANTHROPIC_API_KEY`, `CLAUDE_OAUTH_TOKEN`) должны находиться только в
переменных окружения или локальном `.env`. Не добавляйте `.env`, токены, промпты с
пользовательскими данными и ответы модели в репозиторий или логи.

## Память, наблюдаемость и промоушен

Отчёт по вызовам, cache hit, пользе и отказам:

```bash
uv run python -m app.ai.usage_report
uv run python -m app.ai.usage_report --days 30
```

Просмотр фактов, готовых к переносу в локальные справочники, и сам перенос:

```bash
uv run python -m app.ai.promotion --report
uv run python -m app.ai.promotion
```

Промоушен разрешён только после нескольких независимых согласованных наблюдений.
Единичный уверенный ответ модели не считается знанием. После изменения справочников
нужно проверить diff и запустить тесты.

## Проверка изменений

```bash
uv run pytest tests/ai tests/api
uv run ruff check
uv run ruff format --check
```

Архитектурные гейты, ветки обогащения и контракт наблюдаемости описаны в
[ai-enrichment-architecture.md](ai-enrichment-architecture.md). Подробная установка,
варианты авторизации и troubleshooting — в
[ENABLE_ANTIGRAVITY.md](../ENABLE_ANTIGRAVITY.md). Все доступные переменные с
комментариями приведены в [`.env.example`](../.env.example).
