# 08 — Валидатор выдачи: запрос к backend-API pik.ru — Milestone 4

> Прочитай `_conventions.md` и `docs/pik-url-schema.md` перед началом.

## Контекст

После построения URL надо подтвердить непустую выдачу и вернуть `result_count`.
`pik.ru` — SPA, поэтому проверяем **JSON backend-эндпоинт данных**, а не парсим
HTML-страницу. Это **единственный сетевой вызов на запрос** во всём сервисе.

## Цель

`app/pik/validator.py` — асинхронная функция, которая по `Criteria`/URL делает
запрос к API `pik.ru` и возвращает `result_count` (или признак пустой выдачи).

## Что сделать

1. Определить backend-эндпоинт данных, которым пользуется сам сайт (тот, что
   отдаёт JSON со списком/счётчиком квартир под применённые фильтры). Задокументи-
   ровать его формат в `docs/pik-url-schema.md` (добавить раздел «Data API»).
2. Функция `async def validate(...) -> ValidationResult` на **httpx.AsyncClient**:
   - маппит фильтры в параметры data-API (могут отличаться от параметров
     фронтового URL — свериться);
   - возвращает `ValidationResult(result_count: int, ok: bool)`;
   - таймауты, ретраи по необходимости, аккуратные заголовки (User-Agent).
3. **Устойчивость к отказу сети**: если валидатор недоступен/таймаут — сервис не
   должен падать. Вернуть `result_count = None` и warning «выдача не проверена»,
   но URL всё равно отдать (валидация — best-effort, инвариант «единственный
   сетевой вызов» не должен ронять основную функцию).
4. Fallback-маркер пустой выдачи (текст «По заданным параметрам не удалось ничего
   подобрать») — использовать только для отладки, основная проверка через JSON.

## Правила реализации

- Клиент httpx создаётся/переиспользуется аккуратно (dependency в FastAPI,
  промпт 09), не по разу на каждый вызов без нужды.
- Никаких LLM. Только httpx к `pik.ru`.
- Легко мокируемо: изоляция сетевого вызова за тонким интерфейсом.

## Требования к результату

- Юнит-тесты `tests/pik/test_validator.py` с **замоканным** httpx
  (`respx`/`httpx.MockTransport`):
  - непустая выдача → корректный `result_count`;
  - пустая выдача → `result_count = 0`, `ok = False`;
  - сетевая ошибка/таймаут → `result_count = None` + graceful.
- **Ни одного реального обращения к сети в тестах.**
