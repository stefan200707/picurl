# 09 — POST /build-url end-to-end — Milestone 5

> Прочитай `_conventions.md`, skill `fastapi`, все предыдущие промпты по контрактам.

## Контекст

Собрать пайплайн воедино за единственным эндпоинтом.

## Цель

`app/main.py` — рабочий `POST /build-url`, связывающий
`parse → build_url → validate` и возвращающий ответ по контракту ТЗ.

## Поток обработки

1. Принять `BuildUrlRequest { text }`.
2. `criteria, warnings = parse(text)` (промпт 06).
3. `url = build_url(criteria)` (промпт 07).
4. `validation = await validate(criteria)` (промпт 08, best-effort).
5. Сформировать `BuildUrlResponse`:
   ```json
   {
     "url": "...",
     "criteria": { человекочитаемое представление },
     "result_count": 47,
     "warnings": []
   }
   ```
   `criteria` — публичный вид (промпт 02): `{"rooms":"2","price_max":15000000,
   "metro":["Аэропорт Внуково"],"finish":true,"sort":"price_asc"}`.

## Обработка пустой выдачи (открытый вопрос №2)

Реализуй выбранное на milestone решение (по умолчанию — явное сообщение, не
молчаливая мёртвая ссылка):
- при `result_count == 0`: добавить warning «под критерии ничего не найдено» и/или
  явный флаг «нет вариантов»;
- (опционально, за флагом) стратегия **ослабления наименее принципиального
  критерия**: ослабить (напр. поднять `price_max`, убрать самый мягкий фильтр),
  перестроить URL, снова провалидировать, и **сообщить об ослаблении в warnings**.
Зафиксируй финальное поведение в `CLAUDE.md`.

## Интерфейс: Swagger-форма на `/docs` (без своего фронтенда)

У сервиса **нет собственного фронтенда** и он не нужен: ввод текста идёт через
**автосгенерированную Swagger-форму FastAPI на `/docs`** — это бесплатно, часть
самого фреймворка, отдельный UI писать не требуется. Пользовательский сценарий:

1. Открыть в браузере `http://<host>:<port>/docs`.
2. Раскрыть `POST /build-url`, нажать **Try it out**.
3. Вписать желание в поле `text` request body
   (напр. `"хочу двушку у метро, до 15 млн, с отделкой"`).
4. Нажать **Execute**.
5. Получить в **Response body** JSON с готовой ссылкой (`url`) на `pik.ru`,
   а также `criteria`, `result_count` и `warnings`.

Чтобы эта форма была удобной, обеспечь:
- **Swagger UI включён** (в FastAPI `/docs` доступен по умолчанию — не отключай
  его; `/redoc` можно оставить как есть).
- **Осмысленные метаданные OpenAPI**: у `FastAPI(...)` задан `title`,
  `description` (кратко: «введите желание — получите ссылку на pik.ru») и
  `version`; у эндпоинта — `summary`/`description` и понятный `tags`.
- **Пример запроса прямо в форме**: у поля `text` в `BuildUrlRequest` задан
  `examples`/`json_schema_extra` с эталонной фразой из ТЗ, чтобы поле было
  предзаполнено готовым к нажатию `Execute` примером.
- **Пример ответа** (можно через `responses=` или пример в модели), чтобы в
  Swagger было видно форму JSON со ссылкой ещё до выполнения запроса.

## FastAPI-детали (skill fastapi)

- Стиль `Annotated[..., Depends(...)]`; httpx-клиент валидатора — через
  dependency с корректным жизненным циклом (lifespan/`AsyncClient`).
- Возврат через return-тип модели, не сырой dict.
- Аккуратные коды ошибок (напр. 400 на пустой `text`).

## Требования к результату

- Эндпоинт работает end-to-end (валидатор замокан в тестах).
- Тест `tests/test_build_url.py`: эталонный запрос из ТЗ →
  ожидаемый `url`, `criteria`, `warnings`, `result_count` (с замоканным API).
- Тест пустой выдачи → выбранное поведение.
- Тест запроса с нераспознанным куском → он в `warnings`.
