## Контекст

Промпты 15–20 добавили: гео-слой, карту памяти (Postgres+pgvector), клиента
Claude, интеграцию в эндпоинт и цикл самообучения. Каждый промпт уже требовал
свои юнит-тесты — здесь нужны **сквозные** сценарии, которые доказывают, что
цель задачи выполняется на уровне системы в целом, а не отдельных модулей, и
единая ревизия документации.

## Задача

### 1. Сквозные интеграционные тесты (`tests/integration/test_ai_learning_loop.py`)

С полностью замоканными Anthropic-клиентом и тестовой БД (или in-memory
фейком за тем же интерфейсом, что и `app/ai/memory.py`):

1. **Холодный старт.** Запрос «трёшка в центре, рядом школа и детский сад» →
   `ai_used=True` (нет ни промоутнутых фактов, ни кэша) → мок Anthropic
   вызван ровно 1 раз → ответ содержит `matched_complex_ids` только из
   переданного шорт-листа (санитайз работает).
2. **Повтор похожего запроса.** Тот же смысл, другая формулировка («хочу три
   комнаты у центра, чтобы рядом сад и школа были») → `ai_used=False`,
   `ai_cache_hit=True` → мок Anthropic **не** вызван (семантический кэш
   отработал).
3. **После промоушена.** Прогнать `app.ai.promotion.promote()` над фактами из
   сценария 1 с `observed_count`, искусственно доведённым до порога → третий
   похожий запрос → `ai_used=False`, `ai_cache_hit=False` (ответ пришёл из
   промоутнутого `app/reference/*.json`/`app/geo/`, не из БД вообще) — мок
   Anthropic и обращение к `ai_semantic_cache` не вызваны. Это и есть
   измеримое доказательство требования «бэк сам мог отвечать без ИИ».
4. **Деградация.** `AI_ENRICHMENT_ENABLED=False` → запрос с POI → сервис не
   падает, возвращает URL по деterministic-части критериев + warning.
5. **Галлюцинация.** Мок Anthropic отвечает ЖК, которого не было в
   шорт-листе → санитайз убирает его, в ответе нет мусора, тест явно
   проверяет отсутствие несуществующего id в `criteria.complexes`.
6. **Регрессия v1.** Обычный запрос без гео-семантики («двушка у метро, до 15
   млн, с отделкой») → `ai_used=False`, ИИ-клиент не создаётся/не вызывается
   вовсе, ответ побитово совпадает с поведением до промпта 15.

### 2. Ревизия документации

- `docs/ai-enrichment-architecture.md`: финальная вычитка — все константы/
  пороги/модели, упомянутые как «TBD» или «решить на месте» в промптах 15–20,
  должны быть либо закрыты конкретными значениями (и почему), либо явно
  перенесены в `prompts/_open-questions.md` как всё ещё открытые (не должно
  остаться тихих недосказанностей).
- `CLAUDE.md`:
  - Раздел «Цель проекта» — дополнить одним абзацем, что поверх
    детерминированного билдера URL сервис умеет (опционально, за фиче-флагом)
    интерпретировать POI/гео-намерения через ограниченный ИИ-fallback с
    самообучением, без изменения базового обещания «URL строится
    детерминированно».
  - Раздел «Стек» — добавить итоговый список новых зависимостей
    (Postgres, pgvector, Anthropic SDK, embedding-библиотека, при выборе —

  - Раздел «Карта директорий» — добавить `app/ai/`, `app/geo/`,
    `docs/ai-enrichment-architecture.md`.
  - Новый раздел (или расширение существующего) с пометкой, какие промпты
    выполнены: `Выполнены промпты 13–21 (см. prompts/)` с кратким описанием
    каждого, по аналогии с текущими описаниями промптов 00–12.
- `prompts/README.md`: финальная таблица с промптами 00–21, разбитая на две

### 3. CI/verify

Если в проекте есть общий verify-скрипт (см. project skill `verify` при
фактическом прогоне) — убедиться, что он по-прежнему проходит без
поднятой БД/ключей (`AI_ENRICHMENT_ENABLED=false` по умолчанию, тесты БД/ИИ
изолированы маркером/отдельным test-путём, например `tests/ai/` +
`tests/integration/test_ai_learning_loop.py`, которые либо мокают всё
целиком, либо явно пропускаются (`pytest.mark.skipif`) при отсутствии
`DATABASE_URL` в окружении CI — задокументировать, какой вариант выбран).

## Требования к результату

- `uv run pytest`, `uv run ruff check`, `uv run ruff format --check` зелёные.
- Сценарии 1–6 выше реализованы и проходят.
- Документация (CLAUDE.md, `docs/ai-enrichment-architecture.md`,
  `prompts/README.md`) отражает финальное состояние без противоречий с кодом
  — это последняя проверка перед тем, как считать декомпозицию задачи
  закрытой.
