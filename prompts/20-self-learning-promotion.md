# 20 — Самообучение: промоушен фактов из карты памяти в детерминированный слой — Milestone AI-5

> Прочитай `_conventions.md`, `docs/ai-enrichment-architecture.md`, промпты
> 15, 17 перед началом. Это прямая реализация требования задачи: «всё меньше
> вызовов к ИИ, и всё больше бэк сам мог отвечать без помощи ИИ максимально
> правильно».

## Контекст

Карта памяти (промпт 17) накапливает факты (`ai_structured_facts`) и
семантические Q&A (`ai_semantic_cache`), но сама по себе она **не снижает**
число вызовов ИИ — снижает только повторные попадания в кэш точно такого же/
близкого вопроса. Чтобы бэкенд реально «учился отвечать сам», стабильные
факты нужно периодически **выгружать из БД в тот же детерминированный слой,
которым уже пользуется v1** (`app/reference/*.json`, `app/geo/`) — тогда для
них не нужен ни ИИ, ни БД, ни даже эмбеддинг-инференс: обычный JSON-lookup,
как для метро/округов сегодня.

## Задача

### 1. Критерий промоушена

Факт из `ai_structured_facts` промоутится, если:
- `observed_count >= PROMOTION_MIN_OBSERVATIONS` (порог, например 3 —
  зафиксировать как константу/настройку, обсудить в
  `docs/ai-enrichment-architecture.md`, это открытый вопрос из промпта 15);
- `confidence >= PROMOTION_MIN_CONFIDENCE` (например 0.8);
- `source` ещё не `'promoted'` (не промоутить повторно);
- нет зафиксированного конфликта (см. промпт 17, `store_structured_fact`) с
  более свежим противоречащим наблюдением.

### 2. `app/ai/promotion.py`

- `async def find_promotable_facts(pool) -> list[StructuredFact]` — запрос к
  БД по критерию выше.
- `async def promote(facts: list[StructuredFact]) -> PromotionReport` —
  для `fact_type` вида `is_center` пишет/обновляет флаг в справочнике округов/
  районов (`app/reference/counties.json`/`districts.json` — добавить
  опциональное поле, аналогично `lat`/`lon` в промпте 16, например
  `is_center: bool | None`); для `fact_type` вида `poi_*` пишет в
  `app/reference/poi_cache.json` (или в таблицу `source='geo'`, если БД —
  единственный источник правды по POI, см. решение промпта 16 — не заводить
  третье хранилище, консолидировать).
- Запись — тем же безопасным паттерном мёржа, что и `refresh.py` (промпт 03):
  не затирать существующую ручную докурацию, стабильная сортировка,
  идемпотентность.
- После успешной записи в JSON — `UPDATE ai_structured_facts SET source =
  'promoted' WHERE id = ...` (факт остаётся в БД для истории/аудита, но
  `enrichment.py` (промпт 18) должен проверять сначала промоутнутый
  детерминированный слой и не долбить БД/ИИ за то, что уже есть в JSON —
  см. `resolve_known_facts` в промпте 18).

### 3. Запуск задачи

CLI: `python -m app.ai.promotion` (по аналогии с `python -m
app.reference.refresh`) — можно гонять руками/по cron. Дополнительно
(опционально, если проект уже поднимает воркер) — периодическая задача через
Celery beat (project skill `celery`): один task, расписание раз в сутки,
конфигурация брокера через `DATABASE_URL`/отдельный Redis (см. project skill
`redis-core`, если брокер — Redis) — не обязательное усложнение, если CLI по
cron достаточно для v2, явно выбрать и задокументировать один вариант, не
оба «на всякий случай».

### 4. Метрика «доля вызовов ИИ снижается»

Добавить простой счётчик (в логах через `logger.info` со структурированным
полем, или отдельная таблица `ai_call_log(occurred_at, ai_used, cache_hit,
source)`, заполняемая из `enrichment.py`) и утилитарный отчёт (скрипт или
раздел в `promotion.py --report`), показывающий за период: сколько запросов
потребовали структурного/семантического остатка, из них сколько отвечено
детерминированно/из кэша/через реальный вызов ИИ. Это не обязано быть
дашбордом — достаточно текстового отчёта в stdout, чтобы можно было
подтвердить требование задачи фактическими цифрами после недели работы.

## Требования к результату

- Тесты `tests/ai/test_promotion.py`: фикстура с фактами разной
  наблюдаемости/уверенности → после `promote()` в тестовом
  `app/reference/*.json` (временная копия, не боевые файлы!) появляются
  только те, что прошли порог; повторный запуск — идемпотентен (не дублирует
  записи, не понижает `source` обратно).
- Явный тест на то, что после промоушена `resolve_known_facts` (промпт 18)
  находит факт **без** обращения к БД/карте памяти (мок БД должен быть не
  вызван для уже промоутнутых фактов).
- `uv run pytest`, `uv run ruff check` зелёные.
