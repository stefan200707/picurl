# Общие конвенции проекта (читать перед каждым промптом)

Эти правила действуют во всех промптах декомпозиции. Не дублируются в каждом
файле — держи их в голове постоянно.

## Стек

- **Python 3.12**
- **FastAPI** + **pydantic v2** (тот же стек, что и основной backend, чтобы
  дефолтный verify-скрипт онбординга сгенерировался без сюрпризов)
- **httpx** — единственный сетевой клиент (валидационный запрос к `pik.ru`)
- **rapidfuzz** — fuzzy-матчинг сущностей
- **pytest** — тесты
- **uv** — менеджер пакетов и виртуального окружения
- **ruff** — линтер и форматтер

Проект — **отдельный чистый репозиторий**, без зависимости от кода `workflow-ai`;
общие только конвенции (`uv`, `ruff`).

## Жёсткие архитектурные инварианты

1. **Никаких вызовов LLM/внешних API в рантайме.** Парсинг полностью
   детерминированный (regex + rapidfuzz по локальным JSON-справочникам).
   `workflow-ai` — только инструмент сборки, не рантайм-зависимость.
2. **Единственный сетевой вызов на запрос** — валидационный запрос к
   backend-API `pik.ru` (сайт — SPA, поэтому дёргаем JSON-эндпоинт данных, а не
   парсим HTML). Он должен быть легко мокируемым и опциональным.
3. **Ничего не отбрасывается молча.** Нераспознанные куски текста и ослабленные
   критерии всегда попадают в `warnings` ответа.
4. **Справочники — отдельный кэшируемый слой** (локальный JSON), обновляемый
   скриптом. Рантайм читает их из файлов, в сеть за ними не ходит.

## Структура репозитория (целевая)

```
app/
  main.py            # FastAPI, POST /build-url
  parsing/
    rules.py         # regex/словари (комнатность/цена/площадь/этаж/отделка/сортировка)
    entity_match.py  # скользящее окно + rapidfuzz по справочникам
    schema.py        # Criteria (pydantic)
    parser.py        # фасад: parse(text) -> Criteria + warnings
  reference/
    metro.json, districts.json, complexes.json, ...
    loader.py        # загрузка справочников в память
    refresh.py       # скрипт обновления справочников
  pik/
    url_builder.py   # Criteria -> URL
    validator.py     # проверочный запрос к API pik.ru
tests/
docs/
  pik-url-schema.md  # спецификация URL-схемы (см. промпт 01)
pyproject.toml
```

## Стиль и качество

- Пиши type hints везде; pydantic v2 (без `RootModel`, без «эллипсиса» `...`
  в полях — смотри skill `fastapi`).
- Для FastAPI — стиль `Annotated[..., Depends(...)]`, return-типы вместо
  `response_model`, где возможно.
- Прогоняй `ruff check` и `ruff format` перед завершением.
- Каждый нетривиальный модуль сопровождается юнит-тестами в `tests/`.
- Все публичные функции — с короткими docstring на русском/английском (единый
  выбор по репозиторию).

## Тесты

- `pytest` из корня, тесты в `tests/`, зеркалят структуру `app/`.
- Сетевые вызовы (`validator`, `refresh`) в тестах **всегда замоканы** (никаких
  реальных обращений к `pik.ru` в CI).
- Стремись к высокому покрытию логики парсинга и построения URL (это ядро).

## Обязательное правило про CLAUDE.md

**При каждом изменении структуры/команд/конвенций проекта — обновляй `CLAUDE.md`**
(это прямое требование корневого `CLAUDE.md`). Добавляй: как запускать сервис,
как гонять тесты, как обновлять справочники, где лежат ключевые модули.

## Определение «готово» для любого промпта

- Код написан, типизирован, отформатирован `ruff`.
- Юнит-тесты добавлены и проходят.
- `CLAUDE.md` обновлён, если менялись структура/команды/конвенции.
- Никаких нарушений архитектурных инвариантов выше.
