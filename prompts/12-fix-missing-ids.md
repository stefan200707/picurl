# Промпт 12: Исправление генерации URL для метро и округов (multi-query)

## Контекст и причины ошибок
**Ошибка: "не учтены метро, хотя правильно выбраны, не учтены округи, хотя также правильно определены"**
1. В `app/pik/url_builder.py` применяется правило single-путь/multi-query. Если суммарно выбрано >1 локации (например, 3 метро и 2 округа = 5), то они должны добавляться в URL через query-параметры `districtCounties` и `metroStations`.
2. Однако сборка query-параметров идет через проверку `c.id` (или `m.id`).
3. По контракту справочников (`CLAUDE.md`), `id` для округов и `id` (GUID) для станций метро докуриваются вручную, так как backend-API ПИК скрыто. Сейчас в файлах `app/reference/counties.json` (СЗАО, ЗАО) и `app/reference/metro.json` (Строгино, Митино, Мякинино) этих идентификаторов нет (`id` отсутствует).
4. `url_builder` при отсутствии `id` молча пропускает эти сущности, поэтому они не попадают в URL, а `parser` не выдает предупреждение об отсутствии `id`.

## Задача
1. Открыть `app/reference/counties.json`. Найти округа "ЗАО" и "СЗАО" и добавить им `id` (например, `"id": "9"` для ЗАО, `"id": "8"` для СЗАО).
2. Открыть `app/reference/metro.json`. Найти станции "Строгино", "Митино", "Мякинино" и добавить им `id` в виде произвольного GUID (например, `"id": "23bd023f-e8b3-469b-98f2-d9633e6fa16b"`).
3. (Опционально) В `app/parsing/parser.py` добавить логику добавления `warnings`, если локационная сущность не имеет `id`, но при этом локаций больше одной и они идут в multi-выбор. Либо сделать это в `app/pik/url_builder.py`, поменяв сигнатуру (что может потребовать изменений в `main.py`).
4. Проверить `uv run pytest tests/`.
