# 05 — Матчинг сущностей: скользящее окно + rapidfuzz — Milestone 3

> Прочитай `_conventions.md` и `03-reference-data.md` перед началом.

## Контекст

Метро/округа/районы/ЖК извлекаются fuzzy-матчингом по справочникам. Самое хрупкое
место без LLM — **не сам матчинг** (rapidfuzz справляется), а **выделение из
свободного текста, какой кусок вообще является именем сущности**.

## Цель

`app/parsing/entity_match.py` — функция, которая по тексту и загруженным
справочникам возвращает найденные сущности (с типом, каноническим именем, слагом,
id, score) + «съеденные» диапазоны текста.

## Алгоритм

1. **Скользящее окно** по 1–3 слова по всему тексту. Кандидатами берём окна:
   - с заглавной буквы (имена собственные), и/или
   - идущие сразу после **триггер-предлога**.
   - вне стоп-слов (предлоги, союзы, служебные — завести список).
2. Каждое окно **фаззи-сравнивается со всеми четырьмя справочниками разом**
   (метро/округа/районы/ЖК) через rapidfuzz. Учитывай `aliases`.
3. Совпадения **выше порога** (старт `score ≥ 85`, см. открытый вопрос №4)
   принимаются.
4. **Триггер-предлоги** как подсказка, сужающая круг сравнения до одного
   справочника и повышающая доверие (можно снизить порог):
   - `у метро`, `на метро`, `рядом с метро`, `м.` → метро;
   - `в районе` → районы; `округ`, `в ЮЗАО` → округа; `в ЖК`, `жк` → ЖК.
   - **Но предлог — не единственный способ найти кандидата**: кейс «хочу у Сокола»
     (без слова «метро») должен находиться и без явного триггера.
5. **Разрешение конфликтов**:
   - перекрывающиеся окна → выбрать лучший score / самое длинное разумное окно;
   - несколько кандидатов с близким score («Юго-Западная»/«Юго-Восточная» от
     опечатки) — вернуть топ-1 **и** положить альтернативы в warnings
     (открытый вопрос №5, дефолт — топ-1 + warning).

## Контракт

Функция возвращает структуру вида:
```python
matches: list[EntityMatch]   # type, canonical_name, slug, id, score, span
warnings: list[str]          # неоднозначности/альтернативы
```
где `EntityMatch.type ∈ {metro, county, district, complex}`. Заполнение полей
`Criteria` (single vs multi агрегация) — здесь или в фасаде (промпт 06); согласуй.

## Правила реализации

- Никакой сети. Справочники приходят через `loader` (промпт 03), не грузятся тут.
- rapidfuzz: подбери scorer (напр. `WRatio`/`token_set_ratio`) и обоснуй в
  комментарии/тестах.
- Порог и веса — константы модуля, легко настраиваемые.

## Требования к результату

- Юнит-тесты `tests/parsing/test_entity_match.py`:
  - точное имя, разговорное (алиас), с опечаткой;
  - без предлога («у Сокола»);
  - многословные («Аэропорт Внуково», «Мичуринский парк»);
  - неоднозначность → топ-1 + warning с альтернативами;
  - несколько сущностей одного типа в одном запросе (→ multi).
