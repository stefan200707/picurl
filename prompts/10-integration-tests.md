# 10 — Интеграционные тесты end-to-end с замоканным pik.ru — Milestone 5

> Прочитай `_conventions.md` перед началом.

## Контекст

Финальный milestone: доказать, что весь пайплайн работает вместе на реальных
формулировках, без обращений в сеть.

## Цель

Набор интеграционных тестов `tests/integration/` через `TestClient`/`httpx`,
поднимающих реальное FastAPI-приложение с **замоканным** сетевым слоем `pik.ru`.

## Что покрыть

1. **Эталон ТЗ** (полный цикл):
   `"хочу 2-комнатную у метро Аэропорт Внуково, до 15 млн, с отделкой, сначала дешевле"`
   → `url`, `criteria`, `warnings=[]`, `result_count` из замоканного API.
2. **Разговорные/опечатки**: «хочу двушку у Сокола до 12м с отделкой»,
   «трёшка в Бабушкинском», «студия в ЖК Мичуринский парк подешевле».
3. **Multi-select**: несколько метро/районов → проверить переход путь→query
   (`metroStations=`, `districtLocations=`).
4. **Нераспознанное в warnings**: «двушка рядом с большим парком» → парк в
   `warnings`, остальное — в URL.
5. **Неподдерживаемое**: «вторичка двушка» → warning про вторичку.
6. **Пустая выдача**: замокать API на 0 → выбранное поведение (флаг/ослабление).
7. **Сеть недоступна**: замокать таймаут → `result_count=null` + graceful warning,
   URL всё равно отдан.
8. **Неоднозначность**: опечатка, дающая близкие score → топ-1 + warning с
   альтернативами.

## Правила

- **Ни одного реального сетевого вызова** (мок через `respx`/`MockTransport`).
- Тесты читаемые, табличные где уместно (`parametrize`).
- Прогнать полный `verify`: `ruff check`, `ruff format --check`, `pytest`.
- Убедиться, что покрытие ядра (parser, url_builder) высокое.

## Финальная проверка проекта

- `README.md` и `CLAUDE.md` актуальны (команды, структура, поведение).
